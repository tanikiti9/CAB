## 現在の苦手分析(集計)

過去の学習報告(感想・メモ)から集計した、現時点での苦手なパターン。**現状は感想ベースの定性的な分析**であり、今後は参考書・アプリで解いた問題の**正答率・所要時間**のデータが蓄積し次第、それらも加味して更新していく。

| 科目 | 苦手なパターン | 理由 |
|---|---|---|
| 法則性 | 回転・移動のパターン | 空間的な変化を頭の中でシミュレーションする必要があり、他のパターンより判断が遅い |
| 命令表 | 入れ替え(順序変更)命令 | 複数の図形の位置関係を同時に処理する必要があり、他の命令より時間がかかる |
| 暗号 | 回転・移動・増減のマス目の問題 | 難易度が高く、本番では飛ばす方針にしている |
| 四則演算(四則逆算) | 分数の問題(構成要素4個以上・×÷中心)、割り算が連続する問題 | 分子分母の逆転や通分が絡み、要素数が多いと急激に難化する |

**共通パターン**: 上記はいずれも「同時に扱う要素数が多いと急激に難化する」という共通構造を持つ(詳細は9/3レビュー参照)。要素数が少ない問題は解く、多い問題は原則飛ばす、という判断基準を全科目共通で意識する。

## 2026-08-22 のレビュー(法則性)

塗り(色の変化)は得意で、回転・移動は苦手、という結果が出ている。これは偶然ではなく、要求される処理の性質差によるものだと考えられる。塗りは「白か黒か」という2値の属性を追うだけで済むのに対し、回転・移動は図形の空間的な変化を頭の中でシミュレーションする必要があり、認知的な負荷が明確に高い。①〜⑤のパターンを並列にまんべんなく検討する必要がある、という気づきも、裏を返せば「仮説の絞り込みが早くできていない」ことの表れなので、後述の命令表演習(8/23〜9/1)で確立した「メモに書き出して状態を固定する」という考え方を、法則性の回転・移動にも応用できる可能性がある(例: 角度の変化を数字でメモしながら追う)。「最初の5秒で気づけないと20秒以上かかる」という感覚は、パターン認識が経験依存であることの裏付けであり、量をこなすことが最も効く対策だと考えられる。

## 2026-08-23 のレビュー(命令表)

この回は演習ではなく、10種類の命令の分類と解法手順の体系化に専念した回。感想欄が「特記なし」なのも、まだ実戦投入前の準備段階だったことと整合している。ここで作った「番号を振る→取り消し→逆さま→入れ替え→最後に逆さまを再確認」という手順は、8/22の法則性で見えた「状態をメモに固定する」姿勢の延長線上にあり、科目をまたいで同じ戦略(外部メモ化によるワーキングメモリの節約)が有効だと考えて一貫させている点は良い傾向。一方でこの時点では「取り消し命令を最初に処理する」「逆さまは優先度低め」という優先順位のルールは決めていたが、後の9/1演習で最大のボトルネックになった「入れ替え命令」の扱いについては、まだ手順の中で軽視されていた(単に④番目に処理するとしか決めていない)。この段階では気づきようがない抜け漏れだが、9/1のつまずきの伏線になっている。

## 2026-09-01 のレビュー(命令表・演習)

実測時間(逆さま45秒〜1分30秒、消す15秒〜2分、取り消し25秒〜1分)は、公称の目安である1問25秒を上回っている。ここで「命令表は正答率40〜50%を目安に、解けそうな問題を優先し、難しそうな問題は飛ばす」という方針に切り替えた判断は妥当だと考えられる。CABのような形式は元々「制限時間内に全問を解き切らせる」設計ではなく、取捨選択の速さ自体を測る意図があるとされているため、全問正解を目指さず選別する戦略は理にかなっている。ボトルネックとして特定された「入れ替え命令」は、8/23時点の手順ですでに軽く扱われていた箇所と一致しており、優先順位の再設計(たとえば入れ替えパターンを図形化して覚える、または入れ替え命令が絡む問題は早めに見切りをつける)が次の焦点になりうる。また「図形を消す命令」と「取り消し命令」の違いを混同していたという発見は、命令の対象(図形 vs 命令そのもの)を区別する軸を明示的に持てていなかったことが原因と考えられ、8/23で作った分類(4分類10種類)をより「操作の対象」で整理し直すと、今後同種の混同を防ぎやすくなりそうだ。

## 2026-09-02 のレビュー(暗号)

暗号を「他科目より易しい」と感じた背景には、命令表で負荷が高かった「複数の条件を同時に操作する」タイプの処理(入れ替えなど)が少なく、「共通する変化点を1つ見つければよい」というシンプルな構造であることが影響していると考えられる。「黒矢印・白矢印は同じ色の方向にしか進めない」というルールへの気づきは、暗号を解く上での前提条件(制約条件)を見落とすと法則自体を誤認するという点で重要な学び。マス目の問題を明確に「飛ばす」と判断したのも、9/1で命令表に対して行った「難しい問題は見切りをつける」という取捨選択の考え方が他科目にも自然に波及している良い兆候。

特に注目したいのは「大問(2〜3問)単位で時間を記録していたため、1問あたりの体感時間を実際より長く見積もっていた」という気づき。これは今後の時間管理の精度に関わる重要な発見のため、過去の記録も念のため確認しておきたい。9/1の命令表エントリでは「所要時間(例題3問ずつ)」と明記されており、あちらも複数問の合計時間だった可能性が高い。つまり9/1時点で感じていた「1問25秒は厳しい」という感覚も、実際にはもう少し余裕がある可能性がある。次回、命令表を再演習する際は、可能であれば1問ごとの時間も計測し、9/1の数値と比較検証するとよい。

## 2026-09-03 のレビュー(四則演算・四則逆算)

この回は内容そのものより、まず前提の訂正から始まった点が重要。それまで「電卓不可の暗算」を前提に情報をまとめていたが、実際に解いてみたところ「式中の□に入る数字を求める四則逆算・電卓使用可」という、想定と異なる形式だったことが判明した。事前情報と実際の出題形式にズレが生じるのは珍しいことではなく、実際に解いてみて初めて発覚する類の情報である以上、今後も他の科目で同様の訂正が入る可能性を前提に進めるのが安全。結果的に9/2の指摘([README.md](./README.md)9/2レビュー参照)通り、実測して確かめる姿勢が功を奏した回だと言える。

内容面で興味深いのは、時間がかかる要因が「割り算の連続」「分数の×÷」など操作の種類そのものよりも、**式の構成要素が4個以上になること**に強く依存している点。これは法則性の回転・移動(複数の変化を同時に追う負荷の高さ)や、命令表の入れ替え命令(複数の図形の位置関係を同時に処理する負荷の高さ)と本質的に同じ構造で、CAB全体を通して「同時に扱う要素数が一定を超えると急激に難化する」という共通パターンが見えてきた。これは科目をまたいだ有用な気づきで、「要素数が少ない問題は解く、多い問題は原則飛ばす」という判断基準を全科目共通の指針として明文化できる可能性がある(ROADMAP.mdの「得意・不得意サマリー」に反映済み)。

また、今回は「それぞれ1問◯秒」と単問ごとの時間を明記しており、9/2で見えた「大問単位の計測は体感時間を過大評価させる」という反省が早速活かされている。今後の時間計測も、可能な限りこの粒度(1問単位)を維持すると、科目間の比較がしやすくなる。
